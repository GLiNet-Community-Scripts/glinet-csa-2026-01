Advisory CSA-2026-01 · Community fix

Check your GL.iNet device for the gl-helper malware

On 20 November 2026 GL.iNet said that its cloud remote management had been abused to install malware on some routers and KVM devices. This script checks a device for the known traces, saves the evidence and removes them on request.

Read this first

  • This is community work, not a GL.iNet tool. GL.iNet has not reviewed or endorsed it. Use it at your own risk.
  • It does not replace a factory reset. GL.iNet recommends a reset. The script finds and removes only the traces we know of.
  • In a business network, wait. Talk to your cyber insurer or incident response provider before you change or reset the device.

Run it

Log in to the device over SSH as root. You can read the script first.

  1. Check

    Reads only and prints a report. Nothing is changed.

    wget -q https://app.gl-i.net/csa-2026-01-fix -O gl-helper-triage.sh ; sh gl-helper-triage.sh

  2. Save the evidence

    Writes an archive to /tmp. That is RAM: copy it to your computer before you reboot. It contains your configuration, possibly with Wi-Fi and VPN keys, so don't post it anywhere.

    sh gl-helper-triage.sh --archive

  3. Clean up

    Only if the check found something. Saves the evidence again, stops the malware, removes its files and autostart entries, then checks again.

    sh gl-helper-triage.sh --fix

Don't run netstat on a device you suspect. The malware replaces it. The script never calls it.

Reading the report

LabelMeaning--fix
IOCA known trace of the malwareRemoves it
PERSISTA changed rc.local or root crontab without a reference to the malwareResets it only when an IOC was found
REVIEWAn unusual change that you should look at yourselfNever touches it
INFOContext, for example files installed by a packageNever touches it

Exit codes: 0 clean, 1 traces found, 2 fixed and clean, 3 fix incomplete, 4 error.

What it looks for

The traces come from the cleanup GL.iNet shipped in the KVM firmware RM1PE 1.10.2. That cleanup runs when one of these files exists:

  • /etc/glinet/.cache/gl-helper
  • /etc/glinet/.cache/gb
  • /etc/config/.gl/gl-helper
  • /etc/config/.gl/gb

The script also finds system tools that were replaced (for example netstat), processes started from these paths, and autostart entries that point to them: crontabs, rc.local, init scripts and the lists of files a firmware update keeps. All details are in the README.

Afterwards

  • Keep the evidence archive.
  • KVM: update to the fixed firmware.
  • Router: update without keeping settings. The malware hides in /etc/config, which an update with kept settings preserves.
  • A factory reset wipes everything the malware could have written and is the safe option on both.
  • Check the computer attached to a KVM, and the devices behind a router.
  • Change the device password, your GL.iNet cloud account password and your SSH keys.
